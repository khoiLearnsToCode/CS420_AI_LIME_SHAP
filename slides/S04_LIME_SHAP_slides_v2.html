If a model is accurate, can we trust its explanation?

We test LIME and SHAP on a breast-cancer classifier:

  • Do they agree?
  • Do they give the same answer every run?
  • Do the features they pick actually matter?

LIME and SHAP on the same wrong prediction

Random Forest: P(malignant) = 0.745, but the tumour is benign. Only 2 of the top 5 features match.

    SourceOur experiment design.

    We test each explanation on three things

    • Useful: shows which features raise or lower the prediction
    • Stable: gives the same result when we change the seed or background data
    • Faithful: removing its top features changes the prediction a lot

    High accuracy doesn’t mean the explanation is good.

      SourcesData: Street et al. (1993). Accuracy: our experiment.

      Our data, models and settings

      Data and models

      • Breast Cancer Wisconsin: 569 tumours, 30 features
      • 10 measurements × 3 statistics (mean, error, worst)
      • Class 0 = malignant
      • 80/20 split: 455 train, 114 test
      • Logistic Regression: 98.2% accuracy
      • Random Forest: 95.6% accuracy

      Explainer settings

      • Both explain P(malignant)
      • LIME: 5000 samples, default kernel width ≈ 4.11
      • KernelSHAP: 100 background rows, 2000 coalitions

              LIME fits a simple linear model around one input

              \[\xi(x)=\arg\min_{g\in G}\; L(f,g,\pi_x)+\Omega(g)\] \[L=\sum_{z,z'}\pi_x(z)\,\big(f(z)-g(z')\big)^2,\quad \pi_x(z)=\exp\!\big(-D(x,z)^2/\sigma^2\big)\]

              How it works

              1. PerturbGenerate 5000 points \(z\) around \(x\) and get \(f(z)\)
              2. WeightCloser points get a higher weight \(\pi_x\)
              3. FitFit a sparse linear model \(g\); its coefficients are the explanation

                SourceRibeiro, Singh & Guestrin (2016), KDD.

                Symbols

                \(f,\ x\)
                black box, \(f(x)\) = P(malignant); instance \(x\in\mathbb{R}^{30}\)
                \(z,\ z'\)
                perturbed sample; its on/off form \(z'\in\{0,1\}^N\)
                \(\pi_x,\ \sigma\)
                weight in \((0,1]\); width \(\sigma\): if it is too small the result is noisy; if it is too large it is no longer local
                \(G,\ \Omega\)
                linear models; \(\Omega\) keeps at most \(K\) features
                \(L\)
                weighted squared error

                  Weak points

                  • The kernel and \(\sigma\) are picked by heuristics (Ribeiro et al.)
                  • So the weights don’t have to add up to the prediction (Lundberg & Lee)
                  • The lime library discretises features, so a weight refers to a value range (our note)

                    SourceLundberg & Lee (2017), NeurIPS.

                    SHAP divides the prediction among the features, and the parts add up exactly

                    \[g(z')=\varphi_0+\sum_{j=1}^{M}\varphi_j z'_j,\qquad \varphi_j=\sum_{S\subseteq F\setminus\{j\}}\frac{|S|!\,(M-|S|-1)!}{M!}\Big[f_{S\cup\{j\}}-f_S\Big]\]

                    Symbols

                    \(M,\ F\)
                    number of features (30) and the set of all features
                    \(S,\ f_S\)
                    a subset without \(j\); the prediction when only \(S\) is known
                    \(\varphi_j\)
                    contribution of feature \(j\), in probability units

                      SourceLundberg & Lee (2017), Theorem 1.

                      Theorem 1: Shapley values are the only additive attribution with

                      • Local accuracy: \(g(x')=f(x)\)
                      • Missingness: a missing feature gets 0
                      • Consistency: if the model depends more on a feature, its SHAP value does not go down

                        How to read SHAP values

                        • Baseline: \(\varphi_0\) = average prediction on the background data; a positive \(\varphi_j\) pushes the prediction above it
                        • Sum: \(\varphi_0+\sum_j\varphi_j\) always equals \(f(x)\)

                                                                    One problem with this test

                                                                    Replacing with the mean can create unrealistic inputs, and correlated features can still carry each other’s information.

                                                                      SourceOur analysis.

                                                                      Feature importance tells us what the model looks at. It doesn’t tell us what causes cancer.

                                                                      Correlated features

                                                                      Radius, perimeter and area grow together, so which one gets the higher score depends on the model and the background data.

                                                                      Unrealistic samples

                                                                      Each feature is changed on its own. This can create tumours that don’t exist, for example a large area with a small radius.

                                                                      Model mistakes

                                                                      On the misclassified tumour, the features explain why the model was wrong. They don’t explain malignancy.

                                                                      No real intervention

                                                                      We only change numbers in the model’s input, not anything about a real tumour.

                                                                            When using LIME or SHAP

                                                                            • Report the seed, background data and kernel width
                                                                            • Run it several times and report how stable it is
                                                                            • Run the checks, especially for borderline and wrong predictions
                                                                            • Say “the model relies on X”, not “X causes Y”

                                                                              Limitations and future work

                                                                              Limitations

                                                                              • We only used one dataset, two models and three test cases
                                                                              • No confidence intervals
                                                                              • There is no ground truth, so we can’t say which method is correct
                                                                              • Because LIME discretises features, we only compare ranks and signs
                                                                              • Probability scale and KernelSHAP only

                                                                              Future work

                                                                              • Insertion test
                                                                              • LIME \(R^2\)
                                                                              • TreeSHAP and the log-odds scale
                                                                              • More data and more runs
