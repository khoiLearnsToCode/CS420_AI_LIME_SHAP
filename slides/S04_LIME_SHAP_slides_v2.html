If a model is accurate, can we trust its explanation?

We run LIME and SHAP on a breast-cancer classifier and check three things: do they agree, do they give the same answer each run, and do the features they pick actually matter to the model?

One wrong prediction, explained twice

Random Forest gives P(malignant) = 0.745, but the tumour is actually benign. LIME and SHAP only have 2 features in common in their top 5.

    Model accuracy tells us nothing about the explanation, so we test three things

    Useful

    Tells us which features raise or lower the prediction.

    Stable

    Gives the same result if we change the random seed or the background data.

    Faithful

    If we remove its top features, the prediction should change a lot.

    Setup

      LIME and SHAP explain single predictions of an already-trained model

      Four ways to group XAI methods (and where LIME and SHAP fit)

      • Explainability vs. interpretability: explaining one decision vs. understanding the whole model. Both do the first; the model itself stays a black box.
      • Local vs. global: one instance vs. the whole model. Both are local, but SP-LIME picks a few typical instances to give a global view.
      • Model-specific vs. model-agnostic: looks inside the model vs. only calls its prediction function. LIME and KernelSHAP are agnostic; Linear SHAP and Deep SHAP are model-specific.
      • Intrinsic vs. post-hoc: interpretable by design vs. explained after training. Both are post-hoc and work by perturbing the input.

      Our three main papers (goal, contribution, limitation)

      • Ribeiro et al. (2016). Goal: explain any classifier so users can decide whether to trust it. Contribution: LIME (a sparse linear model fitted around one input) and SP-LIME. Limit: the kernel and σ are set by heuristics, with no guarantees like Shapley values have.
      • Lundberg & Lee (2017). Goal: put existing attribution methods into one framework. Contribution: additive feature attributions, a proof that Shapley values are the only solution, and KernelSHAP. Limit: assumes independent features; results depend on the background data.
      • Mersha et al. (2024). Goal: survey the XAI field. Contribution: four axes (scope, stage, applicability, design) and five criteria: fidelity, consistency, robustness, efficiency, sufficiency. Limit: only a short part on LIME and SHAP; we borrow its criteria loosely, not its exact formulas.

        LIME copies the model around one input with a simple linear model

        1. PerturbGenerate points \(z\) around \(x\) and get \(f(z)\) for each (5000 by default).
        2. WeightPoints closer to \(x\) get a higher weight from the kernel \(\pi_x\).
        3. FitFit a sparse weighted linear model \(g\). Its coefficients are the explanation.
        \[\xi(x)=\arg\min_{g\in G}\; L(f,g,\pi_x)+\Omega(g)\] \[L=\sum_{z,z'}\pi_x(z)\,\big(f(z)-g(z')\big)^2,\quad \pi_x(z)=\exp\!\big(-D(x,z)^2/\sigma^2\big)\]
        \(f,\ x\)
        black box, \(f(x)\in[0,1]\) is P(malignant); instance \(x\in\mathbb{R}^{30}\)
        \(z,\ z'\)
        perturbed sample; its on/off form \(z'\in\{0,1\}^N\)
        \(\pi_x,\ \sigma\)
        weight in \((0,1]\); width \(\sigma>0\): too small gives noisy results, too large stops being local
        \(G,\ \Omega\)
        linear models; \(\Omega(g)=\infty\cdot\mathbb{1}[\lVert w_g\rVert_0>K]\) keeps at most \(K\) features
        \(L\)
        weighted squared error, \(L\ge 0\), in squared probability units

        From Ribeiro et al.: the kernel and \(\sigma\) are set by heuristics, so there is no guarantee like Shapley values have. From Lundberg & Lee: because of these heuristics, LIME can lose local accuracy, so its weights don't have to add up to the prediction. The LIME paper itself doesn't mention this. Our note: the lime library discretises continuous features by default, so each weight refers to the value range the instance falls into.

          SourceEquations, Theorems 1 and 2: Lundberg & Lee (2017), NeurIPS.

          SHAP divides the prediction among the features, and the parts add up exactly

          \[g(z')=\varphi_0+\sum_{j=1}^{M}\varphi_j z'_j,\qquad z'\in\{0,1\}^M\] \[\varphi_j=\sum_{S\subseteq F\setminus\{j\}}\frac{|S|!\,(M-|S|-1)!}{M!}\Big[f_{S\cup\{j\}}-f_S\Big]\]
          \(M,\ F\)
          number of features (30) and the set of all features
          \(S,\ f_S\)
          a subset without \(j\); prediction when only \(S\) is known, the rest averaged over background data
          \(\varphi_j\)
          measured in probability: \(\varphi_0\in[0,1]\), \(\varphi_j\in[-1,1]\)

          Theorem 1: only one additive attribution has

          • local accuracy: \(g(x')=f(x)\)
          • missingness: a missing feature gets 0
          • consistency: if a feature matters more, its credit never drops

          How to read SHAP values

          • Baseline: \(\varphi_0=\mathbb{E}[f(X)]\), the average prediction on the background
          • Sum: \(\varphi_0+\sum_j\varphi_j=f(x)\), always
          • Sign: positive means the feature pushes the prediction above the baseline

          How the two papers connect. Theorem 2 shows that KernelSHAP is just LIME with a particular kernel, loss and regulariser. With LIME’s heuristic choices instead, local accuracy or consistency can fail. On the other hand, KernelSHAP assumes the features are independent, and its result depends on the background data.

            SourceWorked example by the team; closed form from Lundberg & Lee (2017).

            Worked example 1: SHAP values add up to the prediction

            Linear model, independent features, background at the mean:
            \(f(x)=1+2x_1-x_2+0.5x_3\), \(\ \mu=(1,2,4)\), \(\ x=(3,1,6)\)
            Closed form: \(\varphi_j=w_j\,(x_j-\mu_j)\)
            • Baseline \(\varphi_0=f(\mu)=1+2-2+2=3\)
            • Prediction \(f(x)=1+6-1+3=9\)
            • Contributions \(\varphi_1=2(3-1)=4,\ \varphi_2=(-1)(1-2)=1,\ \varphi_3=0.5(6-4)=1\)
            • Check \(3+4+1+1=9=f(x)\); the full Shapley sum gives the same \((4,1,1)\)

            Look at feature 2: its weight is negative, but its contribution is positive because \(x_2\) is below its mean. So the sign depends on both the weight and the instance’s value.

                        Feature importance shows what the model uses, not what causes cancer

                        Why importance is not causation

                        • Correlated features. Worst radius, perimeter and area increase together, so how the credit is split between them depends on the model and the background data.
                        • Unrealistic samples. Both methods change each feature on its own (for KernelSHAP, this is the independence assumption). This creates combinations no real tumour has, like a large area with a small radius, so the model is asked about inputs it never saw.
                        • Model mistakes. On the misclassified tumour, the size features explain why the model was wrong. They say nothing about malignancy.
                        • No real intervention. Changing a value only changes the model’s input. Nothing happens to an actual tumour.

                        Checks we suggest before trusting an explanation

                        StepCriterionStatus here
                        1. Sanity check on a known answer, \(w_j(x_j-\mu_j)\)fidelityWorked example only
                        2. Local fit: LIME \(R^2\); SHAP sums to \(f(x)\)fidelitySHAP only
                        3. Deletion and insertion vs. randomfidelity, sufficiencyDeletion only
                        4. Top-k Jaccard over seeds and backgroundsconsistencyDone
                        5. Small input changes, similar modelsrobustnessNot done

                        One check alone is not enough. An explanation should pass several of them.

                          So, no: a model can be 98% accurate and still have unreliable explanations

                          Agreement

                          For the misclassified tumour, LIME and SHAP have only 2 of 5 top features in common.

                          Stability

                          The top 5 changes from run to run. Mean Jaccard goes down to 0.53 (SHAP) and 0.72 (LIME).

                          Faithfulness

                          Both clearly beat random deletion, but we couldn’t show one is more faithful. Neither tells us about causes.

                          When using LIME or SHAP

                          • Report the seed, background data and kernel width
                          • Run it several times and report how stable it is
                          • Run the checks above, especially for borderline and wrong predictions
                          • Say “the model relies on X”, not “X causes Y”

                          Limitations and future work

                          • Only one dataset, three instances and two models, with no confidence intervals
                          • There is no ground truth for explanations, so we can’t say which method is “correct”
                          • LIME discretises features, so we can only compare ranks and signs, not sizes
                          • We only used the probability scale and KernelSHAP; runtimes are from one machine
                          • Future work: insertion test, LIME \(R^2\), TreeSHAP, log-odds, more data and more runs
